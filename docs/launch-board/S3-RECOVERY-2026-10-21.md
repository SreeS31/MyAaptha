# S3-compatible media integration and recovery - 21 October 2026

Related gates: M14.5 private storage/scanner and M14.6 retention/deletion/recovery. This is reproducible local integration evidence; selected-provider production acceptance remains open.

## Executed checks

The opt-in Java integration test exercises the actual S3MediaObjectStorage adapter against a newly created, disposable MinIO service. The Python harness accepts no external endpoint or bucket, uses only a cached image resolved to its immutable local SHA256 identity, publishes the service on 127.0.0.1 and generates new credentials. Inherited AWS credentials/profiles and Java-option overrides are excluded; empty AWS configuration files disable fallback to owner profiles and metadata lookup is disabled. Synthetic data contains no customer records.

Both plaintext-loopback and TLS variants passed. The final TLS variant verifies:

- A freshly generated certificate is trusted explicitly; the ordinary system trust store rejects that self-signed certificate. Certificate verification is never disabled.
- The real application adapter writes with SSE-S3, and the storage response reports AES256. Plaintext reads match the submitted synthetic bytes.
- Unsigned object downloads return 403; application-generated signed URLs return the expected bytes.
- Adapter deletion creates a delete marker: current reads and a previously issued unversioned signed URL return 404.
- The older object version remains recoverable. Copying that exact version creates a different current version, preserves the original bytes and explicitly retains AES256 encryption.
- The test purges only versions and delete markers from its freshly created synthetic bucket, confirms it is empty and removes the bucket.
- Lifecycle configuration round-trips current-object and noncurrent-version expiration settings. Automatic multi-day expiry is not measured.
- Cleanup removes the service and its anonymous volumes before success is reported. Temporary TLS keys/trust store and synthetic master-key configuration are discarded.

A delete marker does not permanently erase noncurrent versions. The selected provider's approved lifecycle/backup policy must define retention and permanent deletion; the application adapter's ordinary delete operation does not purge all stored versions.

## Reproduce locally

Requires Docker with the cached MinIO image, the existing offline Maven cache, Java/keytool and OpenSSL. The Windows harness locates the existing Git OpenSSL executable when it is not on PATH.

```powershell
python infrastructure/smoke_s3_recovery.py --tls
```

Without --tls the synthetic loopback variant deliberately does not exercise the adapter's encrypted write path. It checks load/delete/signed-read and version recovery only. The opt-in Java test is skipped unless the harness enables it; it refuses a non-loopback endpoint or a bucket outside the generated fixture pattern.
