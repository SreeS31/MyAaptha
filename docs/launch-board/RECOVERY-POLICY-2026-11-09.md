# Deleted-file recovery ? 9 November 2026

The owner selected **90 days** for recovery of deleted files. This is separate from active upload expiry (1/7/30/60/90/180/365/730/1095/1825/3650 days or Never), the default 1 GB allowance and paid storage up to 100 GB.

Prepared configuration: [enable versioning](../../infrastructure/production/media-versioning.json) and [expire noncurrent versions after 90 days](../../infrastructure/production/media-lifecycle.json). These are reviewed input files, not applied cloud settings. Use only the designated private application-media bucket; inspect and merge any existing lifecycle rules before applying a bucket-wide configuration. The backend's S3 deletion omits a version ID, which creates a delete marker when versioning is enabled. Do not grant the ordinary application role permanent version deletion or bucket lifecycle/versioning administration.

The lifecycle contains no current-object expiration, so it cannot override Never or the uploader's chosen active deadline. AWS measures noncurrent age from when a successor version is created (including a delete marker); deletion is asynchronous, with provider day-boundary rounding. This configuration expresses a 90-day recovery policy, not an exact-second purge guarantee. Older overwritten versions have their own noncurrent age. See [AWS lifecycle semantics](https://docs.aws.amazon.com/AmazonS3/latest/userguide/intro-lifecycle-rules.html) and [versioned deletion](https://docs.aws.amazon.com/AmazonS3/latest/userguide/DeletingObjectVersions.html).

Before acceptance: verify versioning is Enabled, private encrypted storage, lifecycle readback, runtime IAM denial of version deletion, synthetic delete/read denial and authorized isolated restoration with matching bytes. Restoring bytes alone must not bypass expired/deleted application metadata, ownership, revoked sharing or quota checks. No self-service undelete endpoint is added by these templates. Production restoration remains an operator procedure requiring authenticated ownership, audit and application metadata recovery. Local filesystem deletion has no S3-versioning protection; it must not be advertised as 90-day recoverable without a separately validated backup system.
